# Win Lifecycle Process Trace — Harness

**Status:** HARNESS ARTIFACT — non-invasive diagnostic tooling for a future human-approved run.

**DO NOT EXECUTE ANY SCRIPT UNTIL YOU HAVE READ AND APPROVED ALL SAFETY CONSTRAINTS.**

---

## Purpose

Captures child-process-creation events (console/shell flashes) during Pi terminal/console lifecycle operations from **outside** Pi — no modification to Pi source, config, registry, services, or persistent system state.

**This is a design-only harness.** It produces artifacts (scripts, configs, schemas) for a future human-approved run. It does not run live monitoring, launch Pi, or claim live evidence.

---

## Lifecycle Paths Covered

| Path | Trigger | Description |
|------|---------|-------------|
| **Cold Start** | Pi launched from scratch | Process tree rooted at Pi executable through first render and idle |
| **Open-from-Terminal** | Pi launched from existing shell | Parent shell → Pi → transient children |
| **Runtime Reload** | `/reload` | Child processes spawned during reload |
| **New Session** | `/new` | New Pi/session process creation or handoff |

## Instrumentation: WMI Only (Default)

- **Primary capture:** `Win32_ProcessStartTrace` via `Register-CimIndicationEvent`
- **Enrichment:** `Win32_Process` queries for command line, executable path, session ID, user SID
- **No elevation required** for default WMI capture
- **No drivers installed**
- **No persistent hooks or scheduled tasks**
- **No Pi process interception**

**ETW/ProcMon capture requires separate explicit human approval** (involves admin rights / drivers).

## Marker Scheme

Action markers follow the planner specification:

```
COLD_START_BEGIN
COLD_START_FIRST_RENDER
COLD_START_END

OPEN_FROM_TERMINAL_BEGIN
OPEN_FROM_TERMINAL_COMMAND_SENT
OPEN_FROM_TERMINAL_ATTACHED
OPEN_FROM_TERMINAL_END

RELOAD_BEGIN
RELOAD_TRIGGER_SENT
RELOAD_POST_IDLE
RELOAD_END

NEW_SESSION_BEGIN
NEW_SESSION_TRIGGER_SENT
NEW_SESSION_RENDER
NEW_SESSION_END
```

Every marker is JSONL with ISO-8601 UTC timestamp, local timestamp, monotonic sequence, and path metadata. See `PiLifecycleEvidence.schema.json` for the exact shape.

## Correlation Windows

| Lifecycle | Primary Bracket | Expanded Window | Max Timeout |
|-----------|----------------|-----------------|-------------|
| Cold Start | `COLD_START_BEGIN → COLD_START_FIRST_RENDER` | `BEGIN - 2s → END + 5s` | 60s |

## Safety / Rollback (Future Approved Run)

When a human eventually approves a live run, the operator must follow these cleanup steps:

1. **Run** `Stop-PiLifecycleTrace.ps1` — writes `TRACE_STOPPED` marker, unregisters WMI subscriptions, flushes evidence files, terminates background jobs
2. **Verify no residual subscriptions** — `Get-EventSubscriber` shows no entries with `Win32_ProcessStartTrace` in SourceObject
3. **Preserve logs** by default — evidence files remain in the run directory
4. **Delete temp logs** only when the human explicitly requests it
5. **Never modify Pi files**
6. **Never modify Windows services or registry**
7. **Treat raw command lines as sensitive** — do not commit, share, or upload unredacted
